# 安全设计

## 网络边界

- union 和 ram 在生产环境只监听回环地址；
- Caddy 是唯一对客户端暴露的入口；
- 管理站、博客站和文件站使用不同主机名；
- Caddy 配置安全响应头、内容安全策略、压缩和访问日志；
- 外部 Sunshine/Proxmox 请求默认校验证书，只有明确受控环境才允许关闭。

不要直接在防火墙中开放 8080 或 5000。

## 信任边界与威胁模型

Union 假设 Linux 主机、`root`、服务账号和 PostgreSQL 管理员属于受信任运维边界。它防止普通客户端直接访问后端、读取已保存凭据或越权写文件，但不能抵御已取得 root、数据库加密主密钥或服务账号权限的攻击者。

Sunshine 与 Proxmox VE 是外部信任域。生产环境强制验证其 TLS 证书；仍应为 Union 创建最小权限账号或 API Token，并限制网络可达范围。

## 认证与会话

- 管理密码使用 bcrypt；
- 未知用户也执行同成本哈希，降低用户名时序枚举；
- bcrypt 并发受信号量限制，避免耗尽阻塞线程池；
- 登录失败采用滑动窗口限流；
- 生产 Cookie 使用安全属性；
- 长效会话令牌不写入 Web Storage，也不在登录 JSON 中返回；
- Cookie 变更请求要求自定义 CSRF 头；
- SSE 使用短期一次性用途票据；
- 会话保存在进程内存，并在认证访问时清理过期项；服务重启会使全部会话失效。

首次管理员密码只用于创建本地私有管理员配置。成功创建后必须从环境文件删除，并在管理台改为长期强密码。

## 凭据加密

Sunshine、Proxmox 和 ram 密码使用 AES-256-GCM 加密后写入 PostgreSQL。v2 密文包含
`UNION_SECRET_KEY_ID`，主密钥通过 `UNION_SECRET_KEY` 注入；旧 v1 密文仍可读取并在后续写入时升级。

- 主密钥必须是 32 字节随机值的 Base64；
- 生产模式不允许自动生成主密钥；
- 运行配置和服务密码必须以加密格式存储；
- API 返回脱敏结构，不回传已有密码；
- ram 生成配置使用 `0600`，启动命令和管理界面会脱敏认证参数。

数据库备份没有主密钥就不能完整恢复；主密钥没有数据库备份也没有业务价值。二者应在同一加密恢复流程中管理。

主密钥轮换必须是“新增密钥、用旧密钥解密、用新密钥重写、验证、再移除旧密钥”的有序流程。当前版本不支持只替换 `UNION_SECRET_KEY` 后自动重加密；直接替换会让已有外部主机凭据不可读。

## 文件系统

- `data/` 权限为 `0700`；
- 私钥和生成配置权限为 `0600`；
- 博客文章路径拒绝绝对路径、父目录、反斜杠和非内容扩展名；
- 数据库也对博客路径、taxonomy 名称和外部主机 JSON 配置做最后一层约束；
- ram 将 URL 解码后只接受安全的 Linux 相对组件；
- 博客资源复制忽略符号链接和隐藏文件，并限制公开扩展名；`blog/data/files/`
  不发布 SVG；
- systemd 只授予 `data/` 和博客构建所需目录写权限。

运行账号不应拥有源码、systemd 单元或 Caddy 配置的写权限。

博客 Markdown/MDX 内容属于管理员信任边界。MDX 可在构建阶段表达组件和脚本能力，
不能接收低权限用户或匿名用户直接投稿；如果未来需要开放投稿，应先改为纯 Markdown
输入并增加内容净化流程。

## 进程管理

- union 对 ram 启停操作串行化；
- 已被外部进程占用的端口不会被强行接管或杀死；
- 停止时先发送 SIGTERM，超时后才强制结束；
- systemd 使用 `KillMode=control-group`、重启策略和启动/停止超时；
- Linux 服务加固包括 `NoNewPrivileges`、`ProtectSystem=strict`、`PrivateDevices` 和受限地址族。

## 审计与日志

变更操作写入 `audit_logs`，包含操作人、目标、请求 ID 和时间。博客内容、taxonomy、RAM 权限和远程实例、Sunshine 主机与远端状态变更都会记录脱敏摘要；不会记录密码、Token 或完整配置 JSON。内部错误记录在服务日志，对客户端只返回通用错误，避免泄漏 SQL、路径和上游细节。

日志仍可能包含主机名、资源 ID 和操作上下文，应按敏感运维数据控制访问和保留期。

## 备份安全

- 备份脚本拒绝未加密输出；
- age 私钥不能与备份归档存放在同一位置；
- 临时解密目录使用 `0700`，恢复后立即删除；
- 定期验证校验和并进行隔离恢复演练；
- 禁止把 dump、运行数据、环境文件或密钥提交到 Git。

## 安全变更检查表

- 是否扩大了监听地址或 Caddy 路由？
- 是否新增了明文凭据、URL token 或日志字段？
- 是否新增了文件写入路径，且经过规范化和边界校验？
- 是否同步更新前后端类型、权限和审计？
- 是否保持生产模式 fail-closed，而不是静默降级？
- 是否补充测试、部署文档和恢复步骤？

## 事件处置

若怀疑主密钥或环境文件泄漏，应立即限制管理入口、保全审计与代理日志、轮换管理员会话及所有外部服务凭据，并生成新的主密钥重新加密配置。仅替换 `UNION_SECRET_KEY` 会导致现有密文不可读，不能作为独立轮换步骤。
